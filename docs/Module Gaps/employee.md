# Module: Employee (webapp)

## 1. Purpose & Current Usage

- **Pages**: `src/pages/Employee/Directory/EmployeeDirectoryPage.tsx` (list — table/grid views, search, sort, status filter, multi-select, Excel export, launches Add Employee wizard) and `src/pages/Employee/Profile/EmployeeProfilePage.tsx` (single-employee profile — header, personal/payroll/education/experience/documents/assets/leave/attendance cards, offboarding trigger). Both are wired into routing at `src/routes/adminRoutes.tsx:20-21, 153-166` (`employee/directory`, `employee/profile/:id`).
- **Onboarding wizard**: `src/features/employee/components/AddEmployeeWizard/AddEmployeeWizard.tsx` drives a multi-step flow (Personal Info → Employment Details → Payroll → System Access → Education → Experience → Documents → Review/Invite) via `WizardContext.tsx`, backed by `useEmployeeWizard.ts` (one `useMutation` per step) and `api/employee.ts`.
- **Profile display**: ~10 card components under `components/EmployeeDetail/` (`EmployeeInfoCard`, `PersonalInfoCard`, `PayrollSummaryCard`, `EducationCard`, `ExperienceCard`, `DocumentsCard`, `AssetsCard`, `LeaveBalanceCard`, `AttendanceMockCard`, `EmployeeDetailHeader`) all fed by one `useEmployeeDetail(id)` hook returning a single flat `EmployeeDetail` aggregate (`types/employeeType.ts:227-243`).
- **Offboarding**: `InitiateOffboardingModal.tsx` (confirm) → `OffboardingCaptureFlow.tsx` (2-step capture: exit details, handover/assets) → `useOffboarding.ts` hooks → `api/offboardingApi.ts`. When an offboarding record exists, `OffboardedEmployeeProfile.tsx` replaces the normal profile view entirely.
- **Dead/unused parts**:
  - `updateEducationMutation`, `deleteEducationMutation`, `updateExperienceMutation`, `deleteExperienceMutation` (`hooks/useEmployeeWizard.ts:116-160`) are fully implemented against real endpoints but are never called by any component (`grep` for their usage outside the hook file returns nothing) — `EducationCard.tsx:40-42` renders a "More options" `MoreHorizontal` button with no `onClick` at all.
  - `EmployeeDirectoryPage.tsx:92-95` — `handleDeleteEmployee` is a placeholder: `showToast('Employee not deleted : ${emp.id}', 'success')`. No delete flow exists anywhere in the feature.
  - `AttendanceMockCard.tsx` is named "mock" but both exported components (`HoursLoggedMockCard`, `AttendanceCalendarMockCard`) fetch real data via `useEmployeeAttendanceHistory` — the name is stale/misleading, not actually dead.
  - No frontend consumer of the backend's birthdays endpoint anywhere in `src/features/employee/` or `src/pages/Employee/` (`grep -rn "birthday"` returns zero hits) — a documented backend capability (`GET /employees/birthdays`, per `brello_server/docs/Module Gaps/user.md`) has no UI at all.

## 2. Intended / Ideal Usage

A correct implementation would: (1) let admins list, search, add, edit, and genuinely delete/deactivate employees; (2) run them through onboarding without leaving unmasked financial/gov-ID data sitting in browser storage; (3) show offboarding/system-access UI state that is only ever asserted once the backend has actually confirmed it, never optimistically computed client-side; (4) mask or role-gate every sensitive field (bank, PAN, Aadhaar, salary) consistently, not just some of them; (5) finish or remove the CRUD affordances it half-built (education/experience edit-delete).

## 3. Cross-Module Connections

- **Depends on**: `department`/`designation` (dropdown/lookup values consumed in the wizard's Employment step), RBAC (`useRoles` hook, `components/AddEmployeeWizard/steps/SystemAccessStep.tsx:28`), the document module (`getUploadUrl`/`uploadDocumentBinary`/`uploadEmployeePhoto` in `api/employee.ts:81-112`, `DocumentsStep.tsx`, `DocumentsCard.tsx`), attendance (`useEmployeeAttendanceHistory.ts`, consumed by `AttendanceMockCard.tsx`), leave (`LeaveBalanceCard.tsx`).
- **Depended on by**: payroll module (`src/pages/payroll/PayrollEmployeeDetailPage.tsx` references employee IDs from this directory), the global employees dropdown (`useEmployeesDropdown`, reused for offboarding handover selection in `OffboardingCaptureFlow.tsx:74-82`).
- **Missing/expected connections — the offboarding UI gives false confidence given the confirmed backend bugs**:
  - `EmployeeProfilePage.tsx:45-47` computes `isExited` purely from `new Date(offboardingStatus.last_working_day) <= now` on the client, with no field from the backend confirming access was actually revoked. This flows into `OffboardedEmployeeProfile.tsx:50-52` (`"Access revoked"` banner text) and the fabricated audit-log row at lines 226-233 (`"System access will be auto-revoked" / by System`). Given the backend's confirmed bug — the offboarding cron updates only `UserProfile.employee_status`, never `User.status`, so terminated employees never actually lose login — this UI text is **actively false** for every exited employee: it tells HR/admins access was revoked when the person can still log in indefinitely.
  - `InitiateOffboardingModal.tsx:27-30` states "This will begin the employee exit process and revoke system access based on the last working day" — a promise the backend does not keep.
  - `SystemAccessStep.tsx` submits a `roleId` via `systemAccessMutation` (`useEmployeeWizard.ts:54-62`), which shows an unconditional `"System access updated"` success toast on any 200 response. Per the backend audit, `updateSystemAccess` writes the role into the unrelated `User.plan_id` column and never touches `user_role_map`, so the grant has zero effect on the employee's actual permissions — the UI gives no indication anything is wrong; the toast looks identical to a real, working grant.

## 4. Gaps

### Structural

- **The whole employee profile is one flat aggregate with no field-level access control on the frontend.** `useEmployeeDetail` returns a single `EmployeeDetail` object (`types/employeeType.ts:227-243`) combining identity, profile, `bankInfo`, `govInfo`, education, experience, assets, documents, and emergency contacts, and every card (`PersonalInfoCard`, `PayrollSummaryCard`, etc.) is rendered unconditionally on `EmployeeProfilePage.tsx` — anyone who can open a profile page sees full bank/PAN/UAN data in one page load, mirroring the backend's own lack of role-based redaction (§ backend audit, Technical). This is a real gap: fixing it purely on the backend won't help if the frontend renders whatever it receives with no masking beyond one field.
- **Half-built CRUD**: education/experience update-delete mutations exist end-to-end (types, API functions, `useMutation` hooks in `useEmployeeWizard.ts:116-160`) but are never wired to any UI control — `EducationCard.tsx:40-42`'s "More options" button is inert. Effort was spent building functionality nothing in the UI can trigger, and users see a button that visibly does nothing.

### Coding

- **Fake delete with a misleading success toast.** `EmployeeDirectoryPage.tsx:92-95`: `handleDeleteEmployee` shows `showToast('Employee not deleted : ${emp.id}', 'success')` — a green "success" toast that literally says the delete didn't happen. There is no real employee-delete flow anywhere in this feature.
- **Noisy success toast on every list fetch.** `hooks/useEmployees.ts:14-20` fires `showToast('Employees fetched successfully', 'success')` on every successful query resolution, including background refetches triggered by pagination/sort/search changes — inconsistent with `useEmployeeDetail.ts`, which only toasts on error.
- **Hardcoded "Active" badge regardless of real status.** `EmployeeDetailHeader.tsx:94-97` renders a fixed `Active` badge with a green dot for every employee shown through this component, never reading `employee.status`/`employeeStatus` — a DRAFT/INVITED (not-yet-activated) employee's own profile header still says "Active".
- **Plaintext bank/gov PII persisted to `localStorage` on every keystroke.** `WizardContext.tsx:70-72` writes the entire add-employee wizard `formData` to `localStorage['brello_onboarding_wizard_state']` on every change; `PayrollStep.tsx:51-57` feeds bank account number, IFSC code, bank name, PAN, and UAN into that same `formData` via a `watch` subscription as the admin types. The result is unmasked financial/government-ID data sitting in the browser's localStorage for as long as the draft exists (until `resetWizard` runs), surviving tab close/reopen.

### Technical

- **UI overstates security-critical outcomes that the backend doesn't deliver.** As detailed in §3: the "Access revoked" / "System access will be auto-revoked" copy in `OffboardedEmployeeProfile.tsx:50-52, 226-233` is computed from a client-side date check, not a backend confirmation, and is false given the known cron bug; `systemAccessMutation`'s unconditional success toast (`useEmployeeWizard.ts:54-62`) gives identical positive feedback whether or not the RBAC grant actually happened (it doesn't). Both are silent-failure traps for HR/IT.
- **Inconsistent PII masking.** `PayrollSummaryCard.tsx:19-23` masks the bank account number (`maskAccountNumber`) but PAN and UAN are rendered in full plaintext at lines 85-100 with no masking at all; `GovInfo` also models `aadhaar`, `esi`, `passport`, `driving_licence` (`types/employeeType.ts:209-218`) which, while not currently rendered, are fetched onto the client with no redaction and would appear in any future card or a network inspector with zero effort.
- **No test coverage.** No `*.test.*`/`*.spec.*` files exist anywhere under `src/features/employee/` or `src/pages/Employee/` — the offboarding and system-access flows, the two areas with confirmed backend correctness bugs, have zero frontend regression protection.
- **Missing feature**: the backend's birthdays endpoint (`GET /employees/birthdays`) has no frontend consumer at all — no widget, no dashboard card, nothing references "birthday" anywhere in this feature's source tree.

## 5. Top 3 Priorities

1. **Correct or remove the offboarding UI's "access revoked" / "auto-revoked" messaging** (`OffboardedEmployeeProfile.tsx`, `InitiateOffboardingModal.tsx`) — until the backend cron bug is fixed, this text actively misleads HR/admins about a live security hole (terminated employees retaining login access).
2. **Stop persisting bank account number/IFSC/PAN/UAN into `localStorage`** from the onboarding wizard (`WizardContext.tsx` + `PayrollStep.tsx`) — this is a real, independent PII exposure in the browser regardless of any backend fix.
3. **Make the "system access updated" toast honest, and finish or delete the dead education/experience edit-delete affordances** — admins are currently told a role grant succeeded when the backend silently drops it, and the inert "More options" buttons/unused mutations are confusing half-finished UI.
